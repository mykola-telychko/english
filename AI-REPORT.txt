Оцінка проекту English Study

Загальний висновок
Проєкт — це оглядова статична навчальна веб-публікація. Поточна структура достатньо зрозуміла для невеликої кількості сторінок, контент доступний і навігація працює. Основна проблема не в коректності окремих сторінок, а в подальшій супроводжуваності: дублювання шаблонів, непридатні імена файлів і відсутність єдиних правил контенту.

Сильні сторони
- Велика кількість практичного навчального матеріалу.
- Є навігація та тематичні розділи: промови, історія, діалоги, математика й ІТ-комунікація.
- Використано окремі CSS-файли, тому презентація частково відокремлена від HTML.
- У деяких сторінках уже є JavaScript, а не виключно статична розмітка.
- README і PLAN задають загальний напрям розвитку проєкту.
- Перевірка поточного стану не виявила HTML-помилок у index.html, daily_english_title.html і page/d11-reich.html.
- Закривальний </p> в кінці останнього діалогу d11-reich.html присутній; попередній пункт про пропущений тег застарів.

Наявні проблеми
- Header, навігація і footer дублюються на кожній сторінці.
- Назви файлів типу d11-reich.html, d5.html і 1-ussp.html не описують їхній зміст.
- Є три CSS-файли; не зрозуміло, який з них є канонічним.
- У довгих сторінках зміст і розмітка практично не розділені.
- ARIA-атрибути і розширені accessibility-практики використовуються недостатньо.
- Багато сторінок мають мінімальні або повторювані заголовки типу ESB.
- Немає автоматичного linting-, HTML-validation- або CI-процесу.
- README описує ідею проєкту, але не містить правил структури, іменування і контенту.
- Дуже довгі діалоги важче редагувати і перевіряти; треба розподіляти їх за рівнем і темою.

Рекомендовані пріоритети

1. Високий: уніфікувати навігацію і назви сторінок
- Визначити канонічну назву кожного розділу.
- Перейменувати криптичні файли:
  - d11-reich.html -> history/third-reich.html
  - d10-gaza-and-israel.html -> history/gaza-israel-conflict.html
  - d5.html -> dialogues/3d-project-meeting.html
  - 1-ussp.html -> speeches/george-washington.html
- Оновити всі внутрішні посилання разом із перейменуванням.
- Не видаляти старі URL одразу; можна тимчасово залишати redirect-сторінки.

2. Високий: усунути дублювання шаблонів
- Спочатку уніфікувати розмітку header, nav і footer у всіх основних сторінках.
- Потім винести їх в спільний шаблон через SSI, Jekyll/Eleventy або невеликий JS-компонент.
- Не переносити весь проєкт одразу на генератор без потреби в 50+ сторінках.

3. Високий: визначити канонічний CSS
- Обрати styles.css основним або об’єднати спільні стилі в один файл.
- Перемістити сторінкові стилі окремими блоками або в styles-pages.css.
- Перевірити контраст, адаптивність, фокусні стані клавіатури і переповнення на mobile.

4. Високий: організувати папки
- pages/speeches/
- pages/dialogues/
- pages/history/
- pages/math/
- pages/it/
- assets/css/
- assets/images/
- assets/audio/
- assets/pdf/
Також варто вести окремі меню для тем і рівнів англійської.

5. Високий: додати автоматичні перевірки
- htmlhint або аналогічна перевірка валідності HTML.
- Перевірка наявності lang, title, h1, alt і посилань.
- prettier або stylelint для єдиного форматування.
- GitHub Actions для перевірки змін перед merge.

6. Середній: покращити SEO і метадані
- Унікальний title для кожної сторінки.
- meta description українською або англійською залежно від аудиторії.
- Додати Open Graph title, description і image.
- Додати canonical-теги лише після стабілізації URL.

7. Середній: покращити доступність
- Перевірити lang, language-атрибути тексту, alt і порядок заголовків.
- Додати aria-label лише там, де native HTML-елемент недостатній.
- Перевірити клавіатурну навігацію, контраст і доступність аудіо/відео.

8. Середній: розділити контент на навчальні типи
- Practice — короткі вправи й введення фраз.
- Dialogue — діалоги для читання й прослуховування.
- Debate — оцінки, припущення й контраргументи.
- Vocabulary — окремі слова й вирази.
- Quiz — перевірка розуміння.
Довгі діалоги слід ділити на логічні частини.

9. Середній: оновити документацію
- README: призначення проєкту, локальний запуск і правила внесення змін.
- CONTRIBUTING.md: назви файлів, структуру папок, заголовки і формат діалогів.
- ARCHITECTURE.md: використані CSS-файли, шаблони, навігація й правила посилань.
- У PLAN.txt позначити виконані завдання, а потім перенести актуальний план у Markdown.

10. Довгостроковий: вибрати формат масштабування
- До появи 50+ однакових статей достатньо простого статичного сайту з єдиним шаблоном.
- Після появи повторюваних моделей контенту варто розглянути Eleventy або Hugo.
- Для матеріалів і вправ можливі JSON/Markdown-файли замість копіювання розмітки.

План початкових кроків
Перша хвиля змін:
1. Створити єдині header/nav/footer.
2. Вибрати канонічний CSS-файл.
3. Перейменувати найважливіші файли і оновити посилання.
4. Додати базову перевірку HTML і broken links.

Друга хвиля змін:
1. Додати title і meta description до ключових сторінок.
2. Перевірити alt, headings, контраст і keyboard navigation.
3. Винести довгі діалоги в окремі секції або фрагменти.
4. Налаштувати GitHub Actions для перевірки змісту й HTML.
